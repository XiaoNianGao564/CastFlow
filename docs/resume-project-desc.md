# CastFlow — 简历项目描述

## 版本一：精简版（约280字）

**CastFlow：自迭代多智能体电力负荷预测系统**

独立设计并实现基于多智能体协作的时序预测自迭代优化平台，服务于铜川市五区县电量负荷预测场景。系统采用自研编排器（非LangChain/LangGraph框架），内置11个专用智能体、4种编排模式（Full Loop / ReAct / 3-Agent Pipeline / Parallel），覆盖数据诊断→代码生成→沙箱执行→误差评估→LLM补丁→迭代收敛的完整闭环。

核心创新：
- **代码级自迭代**：LLM生成最小化代码补丁（非超参调优），结合确定性fallbackPatch（<1ms）与空补丁检测机制，实现低成本、高稳定的自动优化；
- **智能模型选择**：基于数据特征（季节性/趋势/波动性）为31个预测模型（SARIMA/XGBoost/Prophet等）动态打分，自动匹配最优模型；
- **三层记忆系统**：ExperienceStore记录有效/无效策略、SkillStore固化数据-策略指纹、RAGStore索引历史分析文档，实现跨会话知识沉淀与复用；
- **准确率保障**：非提升迭代自动回滚至历史最优，确保预测准确率持续收敛至90%+。

技术栈：TypeScript / Bun / Hono / SolidJS / Python / MySQL / Qwen LLM

## 版本二：数据驱动版（约320字）

**CastFlow：多智能体自迭代时序预测平台**

针对传统机器学习预测 pipeline 人工调参效率低、模型选择依赖经验的问题，独立设计并落地一套多智能体自迭代预测系统，应用于铜川市五区县电力负荷预测。

**系统架构**：自研Coordinator编排器调度11个专用Agent，支持4种编排模式。数据Agent完成完整性校验后，PlannerAgent基于数据特征为31个模型池（统计/机器学习/集成模型）智能打分并选择Top-K候选；CodeGenAgent生成预测代码，ExecutionAgent沙箱执行，EvaluationAgent计算MAPE/MAE/RMSE/准确率；AnalysisAgent根因分析后，PatchAgent生成最小化代码补丁完成迭代优化。

**核心亮点**：
1. **成本优化**：确定性fallbackPatch在<1ms内修复常见语法错误，减少90%+的LLM调用；连续空补丁强制触发兜底策略，避免无效Token消耗；
2. **记忆沉淀**：三层记忆（经验/技能/RAG）实现跨会话策略复用，新任务启动时自动注入历史有效策略；
3. **稳定收敛**：非提升迭代自动回滚至最优版本，准确率从初始60%持续收敛至90%+；
4. **并行加速**：支持多模型并行预测与并行迭代，Top-3候选模型同时运行，取全局最优。

技术栈：Bun / TypeScript / Hono / SolidJS / Python / MySQL / Qwen / SSE实时推送

## 版本三：面试话术版（口语化，便于展开）

"我做了一个叫CastFlow的项目，是一个多智能体自迭代的时序预测系统。传统做法是人去调模型参数，我是让Agent自己去写代码、跑预测、看误差、然后给自己打补丁，不断迭代直到准确率达标。

系统里有11个Agent，我手写的编排器，没有用LangChain那种框架。核心是一个Coordinator负责调度，Planner做数据诊断和模型选择——我们有个31个模型的池子，会根据数据的季节性、趋势这些特征自动打分选最优的。然后CodeGen写Python预测代码，Execution在沙箱里跑，Evaluation算MAPE这些指标，Analysis用LLM分析为什么错了，PatchAgent再生成代码补丁去修。

有几个我觉得比较亮的地方：一个是成本控制，大部分语法错误我用正则规则在1毫秒内修了，不用每次都调LLM；还有一个是记忆系统，每次跑完会把有效策略和无效策略记下来，下次启动新项目的时候自动带进去，避免重复踩坑；最后是稳定性，如果某一轮迭代准确率没提升，会自动回滚到历史最优版本，不会越迭代越差。

技术栈是Bun+TypeScript后端，SolidJS前端，Python跑预测，数据库用MySQL，LLM接的通义千问。"
